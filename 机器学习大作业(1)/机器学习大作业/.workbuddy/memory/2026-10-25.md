## 三项机器学习能力升级（失物匹配 / 内容安全 / 语义检索）
- 新增 `backend/ml/`：`textutil.py`（纯 Python 字 n-gram/TF-IDF/词典切词）、`matcher.py`（失物匹配）、
  `moderation.py`（广告/引战/不文明）、`semantic.py`（市集语义检索）、`eval_all.py`（离线评估）、`__init__.py`
- **关键决策：三项能力全部只用标准库**，不使用 sklearn/jieba/numpy——因为线上跑在 exe 里，
  原始 exe 的 `_internal` 根本没有这些包；纯 Python 让 exe 体积不增加、换电脑零配置
- 失物匹配：字级 TF-IDF + 物品类别词典（类型冲突乘 0.40 否决）+ 地点 + 时间衰减 + 特征词 + 证据加成；
  ≥0.60 高置信互相推送，0.38~0.60 只存 lf_matches 不打扰用户
- 内容安全踩坑记录：**朴素贝叶斯在这份 164 条字级语料上完全不可用（5 折准确率 0.4024）**，
  原因是字级词表数千维、未登录特征的平滑概率主导打分；换成字 1-2gram TF-IDF 类质心（Rocchio）
  后升到 0.8537/宏 F1 0.8374。NB 类保留在模块内作为对比基线（答辩时正好讲这段）
- 规则层用 noisy-OR 合并（不是相加）：相加容易饱和成 1.0 失去分段意义
- 语义检索踩坑：查全率靠"覆盖率"通道而不是余弦——短查询 vs 长文档的余弦天生很低；
  另外 PMI 共现要按语料规模自适应阈值（语料小的时候共现≥2 次筛不出任何词对）
- 新增表：`lf_matches` / `notifications` / `moderation_logs`；新增接口：`/api/lostfound/{id}/matches`、
  `/api/notifications`、`/api/notifications/read`、`/api/moderation/logs`、`/api/market/search`
